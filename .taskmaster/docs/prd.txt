# Test Case Code Generation and Execution PRD

## Project: Testcase Translator Enhancement
## Date: 2025-07-12
## Version: 1.0

## Overview
Enhance the existing Testcase Translator application to support test case selection for code generation, local file management, individual test execution, and example-based prompt enhancement.

## Objectives
1. Enable selective test case code generation
2. Implement local file storage for generated code
3. Support individual Cypress test execution
4. Enhance AI prompt quality with examples

## Requirements

### 1. Test Case Selection for Code Generation
**Description**: Users should be able to select specific test cases and generate Cypress code for the selected items.

**Functional Requirements**:
- Add checkbox selection UI to test case list
- Implement bulk selection (select all/none)
- Add "Generate Code" button for selected test cases
- Display generation progress for multiple selections
- Store generated code with proper associations to test cases

**Technical Requirements**:
- Update frontend components to support multi-selection
- Create API endpoint for batch code generation
- Implement queue system for multiple generation requests
- Update database schema if needed for batch operations

### 2. Generated Code File Management
**Description**: Generated code files should be uploaded locally and their URLs stored in the database.

**Functional Requirements**:
- Save generated Cypress code as .cy.js files
- Create organized directory structure for test files
- Generate unique filenames to avoid conflicts
- Store file paths/URLs in database
- Provide download functionality for generated files

**Technical Requirements**:
- Implement file upload service in backend
- Create uploads directory structure (e.g., /uploads/projects/{projectId}/tests/)
- Add file_url column to generated_code table
- Implement file serving endpoint
- Add file cleanup mechanism for old files

### 3. Individual Cypress Test Execution
**Description**: Users should be able to execute generated Cypress tests individually.

**Functional Requirements**:
- Add "Run Test" button for each generated test
- Display test execution status (running/passed/failed)
- Show test results and logs
- Support video/screenshot capture during execution
- Store execution results in database

**Technical Requirements**:
- Integrate Cypress programmatic API
- Implement test runner service
- Create WebSocket connection for real-time status updates
- Store execution logs and artifacts
- Handle concurrent test executions

### 4. Example Test Cases and Results UI
**Description**: Create an interface to input example test cases and their expected results to enhance AI prompt quality.

**Functional Requirements**:
- Create form for entering example test scenarios
- Support multiple input/output examples
- Allow editing and deletion of examples
- Preview how examples will be included in prompts
- Toggle example inclusion in generation

**Technical Requirements**:
- Create examples table in database
- Design UI components for example management
- Update Mastra AI service to include examples in prompts
- Implement prompt template system
- Add validation for example format

## Database Schema Updates

```sql
-- Add to generated_code table
ALTER TABLE generated_code ADD COLUMN file_url VARCHAR(500);
ALTER TABLE generated_code ADD COLUMN file_path VARCHAR(500);

-- New table for examples
CREATE TABLE test_examples (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id),
  test_scenario TEXT NOT NULL,
  expected_result TEXT NOT NULL,
  cypress_code TEXT,
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Update execution_results table
ALTER TABLE execution_results ADD COLUMN video_url VARCHAR(500);
ALTER TABLE execution_results ADD COLUMN screenshot_urls TEXT[];
```

## API Endpoints

### Code Generation
- `POST /api/test-cases/generate-batch` - Generate code for multiple test cases
- `GET /api/generated-code/:id/download` - Download generated test file

### Test Execution
- `POST /api/test-execution/run/:testId` - Execute individual test
- `GET /api/test-execution/status/:executionId` - Get execution status
- `WS /api/test-execution/live/:executionId` - WebSocket for live updates

### Examples Management
- `GET /api/projects/:projectId/examples` - List all examples
- `POST /api/projects/:projectId/examples` - Create new example
- `PUT /api/examples/:id` - Update example
- `DELETE /api/examples/:id` - Delete example
